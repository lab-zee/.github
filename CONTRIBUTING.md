# Contributing to Lab Z repositories

Thank you for contributing. A repository's local documentation takes
precedence when it provides more specific instructions.

## Before opening a change

1. Search existing issues and pull requests.
2. Use an issue to discuss substantial features, architectural changes, or
   work that changes a public contract.
3. Do not disclose vulnerabilities in public issues; follow
   [SECURITY.md](SECURITY.md).
4. Keep secrets, credentials, proprietary data, and personal contact
   information out of commits, fixtures, screenshots, logs, and issue text.

## Preparing a pull request

- Keep the change focused and explain the problem it solves.
- Follow the repository's setup, style, and architecture conventions.
- Add meaningful tests for changed behavior and failure modes.
- Run all applicable format, lint, typecheck, test, dead-code, and build
  commands locally.
- Update documentation, examples, generated files, and migration notes when
  behavior changes.
- Identify breaking changes, security implications, operational risk, and any
  standards exception.
- Use clear commit messages; do not rewrite shared history without agreement.

By contributing, you agree to follow the
[Code of Conduct](CODE_OF_CONDUCT.md) and confirm that you have the right to
submit the contribution under the repository's license.

## Review

Reviewers may ask for smaller scope, stronger evidence, or follow-up work before
approval. CI passing is necessary but does not replace review. Authors should
resolve conversations explicitly and avoid merging their own unresolved
concerns.
