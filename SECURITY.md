# Security policy

## Reporting a vulnerability

Do not open a public issue, discussion, or pull request for a suspected
vulnerability.

Use the affected repository's **Security** tab and select **Report a
vulnerability** when private vulnerability reporting is enabled. Include:

- the affected repository, version, commit, or deployment;
- impact and realistic attack scenario;
- reproduction steps or a minimal proof of concept;
- known mitigations; and
- whether any details have already been disclosed.

If private vulnerability reporting is unavailable, use an established private
Lab Z maintainer channel and ask for a secure reporting path without first
sharing exploit details. Repository administrators are responsible for
enabling and documenting a private channel; this file cannot enable that
GitHub setting.

Maintainers will acknowledge a usable report, assess severity, coordinate a
fix and release, and credit the reporter when requested and appropriate.
Timelines depend on impact and complexity. Please allow coordinated remediation
before public disclosure.

## Scope

Supported versions are documented by each repository. Reports concerning
unsupported code, social engineering, denial of service without a practical
security impact, or automated scans without a reproducible finding may receive
lower priority.

Never test against data or systems you do not own or have explicit permission
to assess. Do not access, retain, alter, or disclose other people's data.
